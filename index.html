Data & Security

Your data lives on our metal —
not in someone else's cloud.

Royal Bot runs on a private, self-managed server. The database is never exposed to the public internet and is never shared with a third-party provider.

Self-hosted database

MongoDB runs locally on a dedicated machine we control, bound to 127.0.0.1. There is no publicly routable database port — remote access is impossible without an SSH session on the host.

Locked-down host

Key-only SSH with password login disabled, a default-deny firewall, fail2ban, unattended security updates, and authentication enforced on the database with least-privilege application users.

Encrypted backups

Snapshots are encrypted before they leave the machine and stored on offline media. Backups are restore-tested and rotated; expired copies are destroyed, not archived indefinitely.

Minimal collection

We store IDs and settings, not conversations. Message content is only retained where a feature you enabled requires it — like a ticket transcript or a deletion log — and it expires on a schedule.

No selling, no ads

Your data is never sold, rented, or handed to advertisers or analytics brokers. There are no third-party trackers embedded in the bot or in this website.

Deletion on request

Remove the bot and your guild's data is purged on our retention schedule. Want it gone sooner? Ask in the support server and we'll wipe it, usually within 72 hours.

FAQ

Questions, answered.

Is Royal Bot free?

Yes. Every feature listed on this page is free to use. If optional premium perks are ever introduced, existing functionality stays available at no cost.

Why does it ask for so many permissions?

The invite link requests the permissions needed for every module. You can uncheck anything you don't want during the invite flow, or restrict the bot's role afterwards — features you disable simply won't run.

Does the bot read my messages?

It processes messages in real time to run automod and logging, but it doesn't store them unless a feature you turned on needs it — for example a ticket transcript or a message-delete log. Nothing is used for training or profiling.

Where is the data physically stored?

On a private server we administer directly, with the database listening only on the loopback interface. It is not on a shared cloud database service, and no third party has query access.

How do I get my data deleted?

Kick the bot and the associated guild data is purged on our retention schedule. For an immediate wipe, open a ticket in the support server from an account with Manage Server, or email us.

Can I self-host it?

Check the repository for the current licence and setup notes. If the source isn't public, the support server is the place to ask.

What happens during an outage?

Jobs like giveaways and reminders are persisted in the database, so scheduled work resumes as soon as the process is back. Status updates get posted in the support server.
